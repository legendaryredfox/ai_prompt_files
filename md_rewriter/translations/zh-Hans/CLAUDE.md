## 0. 你应当如何行事

### 0.1 安全规则（始终适用，即使对方在不了解风险的情况下要求相反的做法）

1. **绝不向原版游戏卡带（掩膜 ROM）写入或擦除。** 它无法写入，尝试只会造成损坏。对原版卡带只读。如果 `detect` 认不出闪存芯片，就把它当作原版卡带。
2. **擦除或写入闪存卡带之前**，先读出其当前内容并保存为文件，除非对方明确说内容无所谓。写入板子固件之前，先备份出厂固件（4.3 节）。
3. **每一个破坏性操作都需要对方在当时给出“可以”**：向微控制器写固件（ST-Link）、擦除卡带、写入卡带、写入存档。之前对别的事情说过的“可以”不算数。用一句话说明即将发生什么，然后等待。
4. **同一时间只用一个电源**：要么用板子的 USB 线，要么用 ST-Link 的 3.3 V 线，绝不能两者同时。
5. **只有在 USB 线拔掉时才插入或取出卡带。** 卡带和板子共用同样的线路，带电插拔可能损坏其中任何一个。
6. 约 350 °C 的烙铁会烫伤。请对方在通风处操作，焊接后洗手（焊锡可能含铅），并让烙铁冷却。拿板子之前先触摸接地的金属物体放静电，不要抓着卡带插槽拿板子。
7. 绝不索取或记录对方的密码、令牌或个人数据。除非对方要求，否则不要发布任何内容（commit、push、issue）。

### 0.2 工作方式

- 对方可能是电子学新手。**一次只给一步**，说明这一步结束时应该看到什么，对方确认后再继续。使用简短的列表和可直接复制的命令。
- 请对方描述或拍照他们看到的情况（图片胜过文字），并在断定接线正确之前用万用表测量。
- 始终区分**实测事实**与**假设**。本文件标注了哪些在工作台上得到证实，哪些没有。如果对方的板子与本文件有出入，**以他们测得的为准**。
- 如果某一步失败，停下来诊断（第 10 节）。不要为了“看看行不行”而临时对微控制器乱写。
- 编写**不可能**写入或擦除的测试和测试脚本（见 7.4）。破坏性操作只能放在明确确认（`--yes`）之后。

### 0.3 开场问题（先问这些）

1. 电脑的操作系统（Linux 经过测试；Windows 可用，需手动输入命令）。
2. 只想**按出厂状态使用**板子（固件 1.0，不需要焊接），还是要**安装固件 1.1**（需要焊 4 个针脚并有 ST-Link V2）？
3. 手头有什么：ST-Link V2（原装或“U 盘”克隆款）、烙铁、万用表、2.54 mm 4 针排针、母头杜邦线、卡带（哪些？闪存卡？原版卡？）。
4. 是哪种闪存卡带：品牌、标签、卡带 PCB 的照片。记住第 8 节。

## 1. 这块板子是什么、做什么

MD Rewriter 是 Mega Drive（Genesis）卡带的读取/写入器：一颗 STM32 微控制器直接驱动卡带插槽的线路（地址、数据、控制），并通过 USB 以虚拟串口（CDC）与电脑通信。电脑上的应用程序发送命令，固件执行总线周期。

V1.0 板子的事实（EasyEDA Pro 工程，2 层，108.4 × 56.5 mm，没有公开原理图；网表是从 PCB 读出的）：

| 项目 | 事实 |
|------|------|
| 微控制器 | 工程文件写的是 STM32F103VB（128 KiB 闪存、20 KiB RAM）。**第一台实测的板子是 STM32F103xE**（ID `0x414`，512 KiB 闪存，64 KiB RAM）。固件 1.1 按 128 KiB/20 KiB 链接，可在更大的芯片上运行。**务必探测对方的芯片**（4.2），不要假定。 |
| 晶振 | 8 MHz，PLL ×9 = 72 MHz，USB 时钟来自 PLL |
| USB | PA11（D-）和 PA12（D+）各串联 22 Ω；D+ 上有 1.5 kΩ 上拉。枚举为 `0483:5740` “STM32 Virtual ComPort”（CDC）。**没有 DFU。** |
| 电源 | VBUS → PTC（自恢复保险丝）→ 5 V → AMS1117 稳压器 → 3.3 V（MCU）和卡带插槽的 5 V |
| LED | POWER（3.3 V）和 ACT（PC13） |
| 按键 | RESET（带上拉的 NRST） |
| SWD 接口 | **4 个没有丝印的散孔**，竖排，在电容 C10 下方、芯片 U1 右侧、USB-C 接口上方 |
| NRST/BOOT0 | 没有 NRST 焊盘；没有 BOOT0 焊盘（BOOT0 经 R3，10 kΩ，接 GND）；PA9/PA10（ROM 引导程序的 UART）没有焊盘 |

### 引脚图 MCU → 卡带插槽（固件用到的引脚已由固件确认）

| MCU 引脚 | 信号 |
|----------|------|
| `PE0..PE15` | D0..D15（带上拉的输入） |
| `PD0..PD7` | A1..A8 |
| `PD8..PD15` | A9..A16 |
| `PA0..PA6` | A17..A23 |
| `PB4` | /CAS0（读，`MD_RD`） |
| `PB6` | /CE0（`MD_CS`） |
| `PB14` | /LWR（写，`MD_WR`） |
| `PB15` | /VRES（卡带复位） |
| `PB12`、`PB13` | /TIME、M3 |
| `PB5`、`PB7`、`PB8`、`PB9`、`PB11` | /ASEL、/AS、VCLK、/MRES、/CART |
| `PA13`、`PA14` | SWDIO、SWCLK |
| `PC13` | ACT LED |

未连接到 MCU 的：`/UWR`、`/CAS2`、`/DTACK`、EDCLK、YS、HSYNC、VSYNC、SL1、SR1。后果：读卡器从不驱动 /UWR（FlashKit 类闪存卡写字时只译码 /LWR，所以可以工作；依赖 /UWR 或 /CAS2 的卡带，如 I2C 串行 EEPROM，这块板子无法支持）。

没有电平转换：MCU 是 3.3 V，卡带是 5 V。在所有测试过的卡带上都能工作（FT 数据输入和地址输出），但这是已知的设计风险。

### V1.0 板子的已知缺陷（要提醒对方）

- **USB-C 的 CC1/CC2 线上没有 5.1 kΩ 的 Rd 电阻。** USB-C 对 USB-C 的线接到充电器或新款笔记本时可能**不供电**。**请使用带数据线的 USB-A 转 USB-C 线。** 进阶修复：在接口的 A5 和 B5 焊盘与 GND 之间各焊一个 5.1 kΩ 0603 电阻（仅限会焊 0603 的人）。
- 某些批次的自恢复保险丝可能是 0.1 A（BOM 写的是 0.5 A）：请在板上核对；0.1 A 对 MCU + 卡带可能不够。
- USB 和插槽上都没有 TVS/ESD，卡带线上没有串联电阻，插槽 5 V 引脚附近没有去耦。操作要小心。
- ACT LED 接在 PC13（数据手册不建议用该引脚驱动 LED）：能亮，但偏暗。

## 3. 焊接 SWD 接口（仅在安装固件 1.1 时）

### 3.1 4 个焊盘在哪里

俯视，USB-C 在板子底部。从上到下：

```
   ●  3V3
   ●  SWCLK   （PA14，U1 的 76 脚）
   ●  SWDIO   （PA13，U1 的 72 脚）
   ●  GND
 [USB-C]
```

从背面看，竖直顺序相同（3V3 在上），只是看起来像镜像。焊盘顺序是从工程文件读出来的；**焊接前和连接 ST-Link 前，请用万用表确认**：

1. 板子不通电，通断档：一支表笔放在最下面的焊盘，另一支放在 USB-C 接口的金属外壳。应当响（那是 GND）。不响则焊盘或板子（是否放反了？）有误。
2. 之后插上 USB，最上面的焊盘相对 GND 应为 3.3 V。
3. SWCLK 与 SWDIO 信号：由文件推断，随后在工作台上被 ST-Link 接受。如果 `probe`（4.2）什么也找不到，**先把 SWCLK 和 SWDIO 对调**，再怀疑别的。

### 3.2 焊接步骤

1. 用胶带把板子固定住，正面朝上。
2. 把 4 针排针从正面插入，短针朝下，塑料座贴在板子上，针脚笔直且垂直。
3. 把板子翻过来。烙铁 330-350 °C，烙铁头干净并上锡。
4. 烙铁头同时接触针脚和焊盘（约 1 秒）；把焊锡送到焊点上（不是送到烙铁头）1-2 秒；先移开焊锡，再移开烙铁。**先只焊一个针脚。**
5. 好的焊点光亮，呈小火山形，包住焊盘和针脚。如果发暗、发灰、成球或有缝隙：加一点新焊锡重新加热，或用吸锡带吸掉重焊。
6. 检查排针是否仍然笔直。重新加热第一个焊点并按压来纠正。然后焊另外三个（每个约 3 秒；加热过久会掀起焊盘）。
7. 用异丙醇和刷子清洁；用放大镜或手机相机检查：相邻针脚之间没有连锡，也没有缝隙。
8. **万用表，板子不通电：**
   - GND：对 USB-C 外壳响（同前）。
   - 相邻针脚之间（3V3-SWCLK、SWCLK-SWDIO、SWDIO-GND）：**不能**响。响了就是连锡，用吸锡带去掉。
   - 用指甲推每个针脚：都不能晃动。**一根松动的 GND 针脚曾让我们在工作台上浪费了几个小时**：与 ST-Link 的连接每隔几分钟就断一次，看起来像软件故障。只要有任何晃动，就重新加热那个针脚。

### 3.3 可选的 USB-C 修复（CC 电阻）

两个 5.1 kΩ 0603 电阻，一个从 A5 到 GND，一个从 B5 到 GND。仅限会焊 0603 的人。否则用 A→C 线即可解决。

### 3.4 之后拆掉接口（如果想拆）

重新加热一个针脚并用钳子拔出，或者用斜口钳剪开塑料座，再把针脚逐个取出，并用吸锡带清理孔。焊盘不要加热超过几秒：它会翘起。接口留在板子上也完全没问题。

## 4. 通过 SWD 安装固件 1.1（约 1 小时）

### 4.1 为什么 SWD 是唯一的途径

工作台证明**没有 USB 升级**：板子是纯 CDC，没有 DFU 接口；STM32F103 的 ROM 引导程序不支持 USB（只有 PA9/PA10 上的 UART，而它们没有焊盘），固件 1.0 也没有“进入引导程序”的命令。所以必须有 ST-Link 和第 3 节的接口。（将来想要 USB 升级的人，需要先通过 SWD 把引导程序烧录一次：这一点没有做。）

### 4.2 连接 ST-Link 并探测

**先拔掉一切**：板子的 USB 线断开，插槽**为空**。**按 ST-Link 上印的名称**接线，绝不能按颜色或位置（克隆款各不相同；4/6/10 针的“U 盘”ST-Link 不遵循 20 针原装的编号）：

| 焊盘（从上到下） | 信号 | ST-Link 线 |
|------------------|------|-----------|
| 1 | 3V3 | `3.3V`（仅当板子无法接 USB 时；见下） |
| 2 | SWCLK | `SWCLK` |
| 3 | SWDIO | `SWDIO`（有些克隆款印成 `SWIO`） |
| 4 | GND | `GND` |
| 无 | NRST | `RST` 悬空（板子没有焊盘） |

ST-Link 的 `5V` 不连接。原装 20 针 ST-Link：SWCLK = 9 脚，SWDIO = 7 脚，GND = 4 脚（以及 6、8、10……），3V3 = 1 脚（只是电压参考：不给板子供电）。

**供电：** 首选方式（实测稳定）：ST-Link 只接 `GND`、`SWCLK` 和 `SWDIO`，**不接** 3.3 V 线，板子用自己的 USB 线供电。如果板子无法接 USB，则使用 ST-Link 的 `3.3V` 线，同时拔掉 USB 并空着插槽；克隆款的 3.3 V 输出很弱，测试要简短。绝不能两者同时。

用手指按压每一个杜邦接头：接触松动是最常见的问题。这之后才把 ST-Link 插到电脑上。

探测（Linux：`sudo apt install stlink-tools`）：

```
st-info --probe
```

第一台板子的预期结果：`chipid 0x414`、`F1xx_HD`、512 KiB 闪存（寄存器 `0x1FFFF7E0` 为 `0x0200`）、64 KiB SRAM。如果是 `0x410` 且 128 KiB，也有效。如果出现别的 ID 或大小，**先停下来弄清楚再继续**。

如果什么也没找到（`chipid 0x000`、`Failed to connect`、“0 programmers”）：

1. **先查接口上的 GND**（松动的针脚曾是造成数小时间歇性故障的真正原因）。
2. 对调 SWCLK 和 SWDIO。
3. 重新插好每根杜邦线；换一根 ST-Link 线缆/换一个端口。
4. 如果连接时断时续，可循环重试读/写，但**始终要求回读校验**。

### 4.3 备份出厂固件（写入前必须做）

```
st-flash read fw-factory.bin 0x08000000 0x80000     # 512 KiB；如果 st-info 说 128 KiB 则用 0x20000
sha256sum fw-factory.bin > fw-factory.bin.sha256
```

读**两次**并比较。验证：

- 读出的内容**全是 0xFF 或全是 0x00**，说明启用了读保护：**停下**。不要擦除也不要写入。解除保护会擦除芯片，出厂固件将丢失；决定权在对方，并要把这一点说清楚。
- 正常的固件有有效的向量表：第一个字（初始 SP）指向 RAM（`0x2000xxxx`），第二个字（复位）指向闪存（`0x0800xxxx`，奇数）。

第一台板子上：两次读取相同，没有保护，读出 524,288 字节，约 18 KiB 有效，SP `0x20003C30`，复位 `0x08000105`。把备份存放在**两个地方**（另一块磁盘、U 盘）。

### 4.4 获取固件 1.1

原版 MD Rewriter 仓库只提供固件 **1.0**（`Firmware`/`legacy_firmware` 里的 Keil 源码，以及发布页上的 `.hex`）。两条路：

- **路线 A，推荐：** 如果对方有现成的 1.1 二进制，就使用（连同 `.sha256`；用 `sha256sum -c` 检查）。
- **路线 B：** 用 `arm-none-eabi-gcc`（`sudo apt install gcc-arm-none-eabi make`），在原版仓库的代码上应用 6.2 节的改动来构建固件 1.1。注意：
  - 1.0 是用 Keil ARMCC5 `-O3` 编译的。总线等待靠软件延时（`Delay_nop`）完成，所以**时序会随编译器和优化级别变化**。GCC 的 `-O1` 构建在工作台上读写都可用；`-O3` 没有测过。如果改变优化级别，请测量（逻辑分析仪），并通过连续两次读取同一张卡带来验证。
  - 链接脚本必须遵守芯片闪存大小（`0x410` 时是 128 KiB；30 KiB 的 1.1 文件两种都放得下）、20 KiB RAM，并从 `0x08000000` 开始，没有引导程序。
  - 不要用 CubeMX 在已修改的代码上重新生成代码（会抹掉改动）。

### 4.5 写入

仅在备份验证通过、对方说“可以”、并且板子的 USB 已接上（只用 USB 供电）之后：

```
st-flash write md-rewriter-firmware-1.1.0.bin 0x08000000
st-flash read check.bin 0x08000000 <.bin 的大小>      # 然后与 .bin 比较
```

工作台上行之有效的规则：

- **回读校验**闪存并与镜像比较。然后再复位。
- 没有 NRST，复位通过软件完成（AIRCR）。**写入后，把板子的 USB 线拔下再插上**：软件复位不一定能让板子重新在 USB 上枚举。
- 如果芯片里的内容与你做的备份不同（换了一台？另一个镜像？），写入前**先停下并重新备份**。绝不在没有备份现有内容的情况下写入。
- 回到出厂固件：把 `fw-factory.bin` 写回去，并回读比较。
- 如果板子不再响应 SWD（这没有发生过），退路是 BOOT0 为高电平的 ROM 引导程序（把 R3 的 BOOT0 一侧接到 3.3 V），它只通过 PA9/PA10 的 UART 通信，而这两个引脚没有焊盘（LQFP100 的 68/69 脚）：需要细间距飞线。所以备份和校验没有商量余地。

### 4.6 检查

```
lsusb | grep 0483:5740           # 板子出现
```

然后使用应用程序/CLI 的连接命令（第 7 节）。固件 1.1 在连接横幅之后立即打印 `FWVER:1.1.0`。

## 5. 与电脑的 USB 接口

### 5.1 权限与端口

- Linux：板子成为 `/dev/ttyACM0`（或类似）。授予访问权限：`sudo usermod -aG dialout $USER` 并**注销再登录**，或者安装 udev 规则（VID `0483`、PID `5740`、`MODE="0660"`、`GROUP="dialout"`，以及 `ENV{ID_MM_DEVICE_IGNORE}="1"` 让 ModemManager 不去碰该端口）。然后重新插拔线缆。
- Windows：显示为 COM 口。系统提示时安装“STM32 Virtual ComPort”驱动。
- `permission denied` 是串口权限问题。如果板子没有出现：换一根线（带数据线）和另一个端口；POWER LED 必须亮。

### 5.2 串口协议（固件 1.0，以及 1.1 增加的部分）

在出厂固件上观察到，并在 1.1 中保留（1.1 只增加）。电脑发出的命令包：`[cmd] AA 55 AA BB [参数...]`。

| 命令 | 含义 |
|------|------|
| `0C` | 连接。1.1 在横幅后增加第二行 `FWVER:<版本>` |
| `0D` | detect：固件打印 `FLASHID:` 和一行芯片信息（1.1：`FLASHID:%02X%02X`、`CHIPINFO:`） |
| `0A` | 读 ROM（参数 = 大小：`01` 512K、`02` 1M、`03` 2M、`04` 4M；1.1 另有 `05` = 8M） |
| `1A` | 读存档 RAM（参数 `01` = 32K，否则 8K） |
| `0B` | 写一个 ROM 块（参数：块在 bank 内的索引、bank） |
| `1B` | 写一个存档块 |
| `0E` | 全部擦除（芯片和 SRAM） |
| `1E` | 按大小擦除（参数 `01`..`06`，或 `00` 加 3 字节地址） |
| `2E` | 擦除一个扇区 |
| `0F` | 清空缓冲区 |
| `3A` | 仅 1.1：通过 SSF2 映射器读取（参数 = 512 KiB 页数）；**尚未在卡带上测试** |

格式：

- **读取：** 固件先发文本 `... DUMP START!!!\r\n`，然后是 N 个 1024 字节的原始块（512K 到 4M 分别为 512、1024、2048 或 4096 块；存档为 32 或 8；1.1 的 8M 为 8192），最后是 `DUMPER ROM FINISH!!!\r\n`（或 `DUMPER RAM FINISH!!!\r\n`）。
- **写块：** 电脑先发 **1024 字节原始数据，再发 7 字节的 `0B`/`1B` 命令**。固件回复 `ADD:0x... WRITE OK\r\n`（ROM）或 `... WRITE GK\r\n`（存档）。当某个字没有被编程时，1.1 回复 `ADD:0x<字地址> WRITE TIMEOUT`。
- **细节语义的权威来源**（每个参数的确切含义、bank 大小、`1E` 的代码）：原版仓库里的 1.0 固件代码（`main.c` 和 `MD.c`）。**实现之前请在那里核对**；这张表来自工作台观察。

### 5.3 固件的怪癖（在工作台上学到，对 1.0 和 1.1 都成立）

1. **回答 `detect` 之后，固件等待 100 ms，然后才清空输入缓冲区。** 在这个窗口内发送的字节会丢失。实际表现：紧跟 `detect` 之后发送的第一个写块消失，电脑一直等待一个永远不会到来的确认（`The device did not confirm block 1`）。**电脑端的解决办法：`detect` 之后把下一条命令延后 250 ms。** 任何与读卡器通信的工具都会受此影响。
2. **在端口刚被重新打开之后立即到达的 `connect` 可能被忽略。** 重试一次 `connect`，或者在连续运行的进程之间等待 0.3 秒。
3. 烧录固件之后，重新插拔 USB（4.5 节）。
4. 实测速度：读 2 MiB 用时 10-12.5 秒（约 166-214 KiB/s）；8 MiB 约 48 秒。

## 6. 固件 1.0 到 1.1 改了什么、为什么

### 6.1 1.0 在快速闪存卡上的缺陷

在工作台上用 S29GL064N 卡带：**固件 1.0 只对每隔一个字编程**，因为它不等待芯片写完每个字。没有任何字是错的；一半保持空白（`0xFFFF`）。应用程序里的症状：写入结束，校验失败（`Verification failed: ... bytes differ`）。可以通过只重写缺失的字来绕过（8 轮，2 MiB 约 2 分钟），但正确的做法是修好固件。

### 6.2 1.1 的改动（取得良好结果的最小集合）

从 1.0 源码出发，应用：

1. **每编程一个字之后做 DQ7 数据轮询。** AMD 编程序列：`AA`@`555`、`55`@`2AA`、`A0`@`555`，然后 数据@地址（字地址）。每个字之后，读取被编程的地址，直到 DQ7 等于所写数据的第 7 位；如果 DQ5 置位（而 DQ7 仍不匹配），说明芯片放弃了：发送复位（`F0`），停止并回复 `WRITE TIMEOUT`。限制读取次数。让总线在输出和输入之间快速切换（直接访问寄存器），避免轮询太慢。实测结果：一次完成的正确写入。
2. **芯片识别（autoselect）**：在一次 autoselect 会话中读取字 `00`、`01`、`0E`、`0F`，打印带 4 位十六进制的 `FLASHID:`（S29GL064N 为 `017E`），并在名称表中映射。
3. **小扇区擦除**：64 KiB 以下按 8 KiB 步进擦除（每个扇区命令 `30`），之后用 64 KiB 扇区。原因见 8.3。
4. 8 MiB 读取（代码 `05`）、`FWVER:`、`WRITE TIMEOUT` 输出，以及（如有需要）对未知芯片的 CFI 查询。
5. 可选：写缓冲编程（`25`/`29`，每次操作 16 个字）已实现，但**尚未在卡带上测试**（默认关闭）。
6. 除此之外不要动：其余保持与 1.0 相同，旧应用程序才能继续工作。

用 1.1 实测的时间（S29GL064N）：擦除 2 MiB 6-9 秒；写入 2 MiB 约 79 秒（含回读校验约 90 秒）。

### 6.3 没有板子时测试固件

值得把真实的 `MD.c` 在电脑上对着 **AMD 闪存芯片模型**编译（autoselect、带 DQ7/DQ6/DQ5 的编程、扇区擦除、忙时忽略命令的芯片、在布局上“撒谎”的芯片）。它在板子到手之前就抓到了真实错误（例如擦除恰好在两次状态读取之间完成时，DQ5 在 `0xFF` 上被误读）。但模型只是假设：**只有板子证明的才算数**。

## 7. 电脑上的应用程序

### 7.1 现有的东西

原版 MD Rewriter 带有 Qt 应用程序（`Software/`）。参考项目对它做了改进：接受不超过 4 MiB 的任意偶数大小 ROM，转换 `.smd`，通过回读验证写入，显示芯片名称，处理 `WRITE TIMEOUT`，仅当固件报告 `FWVER:` 时才提供 8 MiB，并有为脚本和智能体设计的**命令行**（`mdrewriter-cli`）。

Linux，Qt 6（在 Linux Mint 22 + Qt 6.4 上测试）：

```
sudo apt install build-essential qt6-base-dev qt6-serialport-dev qt6-tools-dev qt6-l10n-tools
cd Software && qmake6 MDRewriter.pro && make -j"$(nproc)" && ./MDRewriter
```

Windows：安装 Qt，用 Qt Creator 打开 `.pro`，或使用发布页上现成的可执行文件。

### 7.2 如果对方不想用 Qt

读取只需要一个用 `pyserial` 的简单 Python 客户端：打开端口，发送 `0C AA 55 AA BB`（连接），等 0.3 秒，发送 `0D AA 55 AA BB`（detect），**等 250 ms**，发送 `0A AA 55 AA BB 03`（2 MiB），读取直到 `DUMP START!!!`，接收 `2048 × 1024` 字节并寻找 `DUMPER ROM FINISH!!!`。通过打印板子的回答来了解横幅和确切文本（不要猜）。要写入，遵循 5.2 的格式，并且**只在擦除之后**。

### 7.3 推荐的 CLI 约定（用在对方的项目中）

- 只读命令：`ports`、`info`、`detect`、`read-rom`、`read-save`、`verify`、`compare`、`rominfo`。
- 会改变卡带的命令（`write-rom`、`write-save`、`erase`）没有 `--yes` 就**拒绝**（退出码 4），并提供 `--dry-run`。写入之前，CLI 检查芯片（`connect`、`detect`，然后写）：如果固件没有打印芯片 ID、ROM 比芯片大，或芯片需要只有较新固件才发送的命令集，就拒绝。
- `read-*` 没有 `--yes` 不覆盖已存在的文件；以原子方式写入。
- `--json` 输出和不同的退出码：0 成功，1 操作失败，2 用法错误，3 无设备，4 缺少 `--yes`，5 文件错误。
- 默认写入后**回读并比较**。在工作台上，校验曾经抓到过一次读错的位（字节 `0xAAB`，`0x04` 读成 `0x00`，未能复现）：没有理由不要关闭校验。
- 用于自动化测试的**假固件**（模拟器），带有重现 5.3 节怪癖的选项。

### 7.4 只读的工作台测试套件

编写（或让智能体编写）一个脚本，**只通过读命令白名单**调用 CLI，并拒绝 `--yes`。证明有用的检查：

- 无卡带：板子枚举为 `0483:5740`；连续重连 10 次；`detect` 回答 `FFFF` 且不命名任何芯片；对空插槽两次读取 512K 的结果相同且**全为 `0xFF`**（证明 D0-D15 上拉有效）。
- 有卡带：两次读取相同；大小；`SEGA` 头；头中的 ROM 大小；头校验和（作为信息，不算失败）；较小的读取等于较大读取的前缀；数据位（每一位应在约 30-40% 的字中为 1：没有卡死的位）；不同的 32 KiB 块数量（地址线卡死会产生重复）；两次存档读取相同。

参考结果：在每台设备上，空插槽读出的都应全是 `0xFF`。如果不是，要怀疑上拉、焊锡短路，或插槽里忘了拿走的卡带。

## 8. 关于卡带的发现（写入任何东西之前先读）

测试过：一张原版掩膜 ROM 卡带（Rolling Thunder 2，Namco），两张 S29GL064N 闪存卡（其中一张来自 KY Technology），以及一个 2 MiB 游戏（Metal Gear），在两张卡上都写入并校验过。做测试的人确认**写入的卡带在真实的 Mega Drive 上运行正常**。

### 8.1 原版卡带（掩膜 ROM）

- `detect` 显示 `FLASHID` 为 `0000`/`00`/`FFFF` 且没有芯片：这是正常的。**绝不写入。**
- 比卡带更大的读取是**镜像**：从 1 MiB 游戏读取 2 MiB 会得到两遍相同的镜像（高位地址线没有译码）。应用程序不检测大小：由使用者选择；更大的读取会重复内容。以头中的大小（`ROM size`）为准。
- 原版卡带的头校验和也可能对不上（Rolling Thunder 2 就是如此：头中为 `BEB6`，累加和 `11B1`）。两次相同的读取、正常的数据位和没有地址混叠，说明读取是对的，但只有参考转储（No-Intro）才能消除疑问：**仍然悬而未决**。

### 8.2 KY / FlashKit 类闪存卡带：**2 MiB 的限制**

**最重要的结果：** 测试过的两张闪存卡最多只能放 **2 MiB 的游戏**，尽管芯片（S29GL064N）有 8 MiB。症状：

- 在 2 MiB 以上擦除或写入会失败：`erase 4M` 约 23 秒后停止，提示 `A sector did not finish erasing in time`；擦除字节地址 ≥ 2 MiB 的扇区会得到 `ERASE TIMEOUT!`。
- 在 2 MiB 以上读取看到的是**存档 SRAM**，不是闪存：每隔一个字节是 `0xFF`，其余字节重复存档文本（在 KY 卡带上出现了游戏名：`ff 52 ff 41 ff 47 ff 4e ...`）。读取 8 MiB 会得到同样的 4 MiB 两遍。

**原因（来自 FlashKit 卡带参考设计 `cart-md-v1.2.pcb`，并由行为证实）：** 卡带使用 74HC139 译码器，只有当 2 MiB 地址线为低时闪存的 /CE 才有效；为高时同一个译码器选中 SRAM。闪存的 A21 引脚接 GND，连接器的 A21/A22 线哪里也没接。**这是卡带本身的结构，不是读卡器或固件的缺陷。**

我们试过用原版编程器的寄存器写入（`$A13000` = `0x0000`/`0x0001`/`0xFFFF`，`$A130F1` = `0`/`1`）以及一次映射器写周期（`/TIME` 和 `/LWR` 为低，`/CE0` 为高）把闪存映射到 SRAM 窗口之上：**毫无变化**（只有一个 RAM 字节变了，正如写 RAM 会造成的那样）。所以这些卡带里没有这个寄存器，**2 MiB 就是上限**。

能放下的：几乎所有 Mega Drive 游戏（多数在 512 KiB 到 2 MiB）。放不下的：大于 2 MiB 的游戏（例如 Super Street Fighter II，4 MiB，带映射器）。它们需要另一种卡带：没有该译码器的普通 4 MiB 闪存卡（例如开源项目 `MD-Flash-Cart-4MB`，使用 MX29LV320 或 MX29L3211），或带映射器的卡带。**你的智能体必须在对这些卡带写入或擦除 2 MiB 以上之前发出警告。**

### 8.3 ID 相同但扇区布局不同的两张卡带

两张卡带都回答 `FLASHID:017E` 和相同的 CFI 查询，在各方面看起来都一样，但是：

- 一张的**第一个 64 KiB 扇区是均匀的**（在 `0x1000` 字处发一次扇区擦除命令就能清掉 64 KiB）。
- 另一张（KY）开头有**八个 8 KiB 扇区**（引导扇区）：要清掉同样的 64 KiB 需要擦除八次。如果固件一次擦 64 KiB，会剩下 56,544 字节仍是已编程状态，下一次写入会在第一个脏扇区就出现 `WRITE TIMEOUT`。
- 额外的 autoselect 代码（周期 `0E/0F`）在两张卡上分别是 `017E1001` 和 `017E1000`，但基于它们的规则是错的；CFI 扇区字（`2C..34h`）在两张卡上给出相同的值，并且**在不同会话之间发生变化**（先是 `...7F...`，后来是 `...7E...`）。**实际结论：不要相信 ID、autoselect 或 CFI 来选择擦除布局。前 64 KiB 始终按 8 KiB 步进擦除。** 两张卡都能工作，只多花一点时间。
- 把芯片的额外代码（`Chip codes 017E1001`）和 CFI 查询作为**信息**展示给用户，绝不作为决策依据。

### 8.4 闪存写入规则

- 闪存只能从 1 变成 0。**写入前要擦除。** 在没有擦除的数据上写入，会在约 0.4 秒内得到 `WRITE TIMEOUT`，板子继续响应：这是安全且在预期之内的失败。
- 在已写入的数据上写入**相同的数据**不会报错（没有需要改变的位）。要证明超时检测有效，请写入不同的数据（例如取反的镜像）。
- 擦除 2 MiB 不会擦除芯片的其余部分。更高地址的内容仍留在那里（其中一张卡带里就有旧数据）。
- 测试过的 S29GL064N 卡带，其中一张带有**无电池的存档 RAM**（PCB 1.4 上还有 FRAM）：`read-save` 可用；**在没弄懂地址映射之前，不要在闪存卡上测试 `write-save`**，因为存档窗口可能与闪存空间重合，写到那里就成了芯片内部的一次总线周期。
- 擦除之前对卡带做一次转储是保险。把它留好。

### 8.5 芯片和命令（便于扩展支持的摘要）

| 芯片 | ID（厂商+设备） | 命令 |
|------|-----------------|------|
| S29GL064N（Spansion/Cypress） | `01 7E` | AMD，解锁 `555h/2AAh` |
| MX29LV640EB/ET | `C2 CB` / `C2 C9`（`C9` 未确认） | AMD 555h |
| M29W640D/G | `20 DF`、`20 DE`、`20 7E` | AMD 555h |
| SST39VF6401B/6402B | `BF 236D` | AMD 555h，块擦除用 `50h` |
| M29W320DT/DB、M29W320ET/EB | `20 CA/CB/56/57` | AMD 555h；“T” = 引导块在顶部（最后 64 KiB 分成八个 8 KiB 扇区） |
| MX29LV320T/B | `C2 A7/A8` | AMD 555h |
| MX29L3211 | `C2 F9` | AMD，解锁 `5555h/2AAAh`；没有页编程 |
| Intel PA28F400 | `89 70/71` | Intel/Sharp 系列（`FFh`、`90h`、`40h`、`20h`+`D0h`、`70h`/`50h`） |

只有 S29GL064N **在硬件上得到了证实**。其余的来自电脑上的模型和对数据手册的阅读：**第一次写入之前请阅读芯片的数据手册**。

### 8.6 未测试的内容（要告诉对方）

SSF2 映射器读取（命令 `3A`）、Sega Lock-on、Open EverDrive、EverDrive v2、Magistr-16、MX26L6420、I2C/SPI 串行存档（板子上缺 `/UWR` 和 `/CAS2`）、Master System/Game Gear（接口不同）、写入过程中断电、写缓冲编程、其他品牌的闪存卡、闪存卡上的 `write-save`、在没有 FlashKit 译码器的卡带上写入 2 MiB 以上。

## 9. 智能体带领的完整流程

只有在对方确认每个阶段之后才继续。

**阶段 1. 了解对方（0.3）。** 提开场问题。

**阶段 2. 按出厂状态使用（不焊接）。**
1. 安装应用程序（7.1）并配置串口权限（5.1）。
2. 给板子供电（A→C 线），不插卡带：POWER LED 亮；`lsusb` 显示 `0483:5740`。
3. 在应用程序中 `Connect`（或 `mdrewriter-cli info`）：“Device identified”和固件 `1.0`。
4. **空插槽：** `detect` 找不到芯片；读取空插槽只得到 `0xFF`。
5. 拔掉 USB，插入一张原版卡带（标签朝向“CART FRONT”箭头，笔直，不要摇晃），再接上 USB，`detect`，读取 2 MiB 两次并比较。结果不同 = 接触不良：用异丙醇清洁卡带触点并重新插好。

**阶段 3. 焊接和检查（第 3 节）**，仅当要安装固件 1.1。

**阶段 4. SWD：探测、备份、写入 1.1、检查（第 4 节）。**

**阶段 5. 测试这台设备（下表），按此顺序。** 如果某项失败，停下并转到第 10 节。

## 10. 诊断

| 症状 | 怎么做 |
|------|--------|
| 电脑上看不到板子 | 带数据线的 USB 线（A→C）；换端口；POWER LED 是否亮？USB-C 没有 Rd 时，C→C 线可能无法供电（第 1 节） |
| `permission denied` | 加入 `dialout` 组并重新登录，或安装 udev 规则（5.1） |
| `st-info` 找不到芯片（`chipid 0x000`、`Failed to connect`） | 先查接口上的 GND；对调 SWCLK/SWDIO；重新插好杜邦线；换 ST-Link 线缆/端口；检查通断和连锡（3.2） |
| 备份读出全是 `0xFF`/`0x00` | 读保护。**停下。** 不要擦除或写入（4.3） |
| 烧录后板子在 USB 上看不到 | 把板子的 USB 线拔下再插上 |
| 第一个写块没有得到确认 | `detect` 之后等待 250 ms（5.3） |
| 紧跟另一条命令后的 `connect` 没有回应 | 重试一次 `connect` / 等待 0.3 秒 |
| `detect` 说未知芯片 | 很可能是原版（掩膜 ROM）或表外的芯片：**不要写入** |
| `did not finish erasing` / `ERASE TIMEOUT` | 不是闪存、已损坏、**或请求超过 2 MiB**（8.2），或擦除没有按 8 KiB 扇区逐个进行（8.3） |
| `WRITE TIMEOUT` | 该区域没有先擦除；擦除后重新写入（8.4） |
| 校验失败 | 清洁触点，换一根 USB 线，重复擦除+写入。固件 1.0 在 S29GL064N 上就是 6.1 节的缺陷 |
| 同一张卡带两次读取不同 | 接触不良：用异丙醇清洁并重新插好 |
| 比卡带更大的读取重复内容 | 这是镜像（8.1）或闪存卡的 SRAM 窗口（8.2）：正常 |
| 写入的游戏在主机上无法启动 | 确认是有效的 ROM（`SEGA` 头）、不超过 2 MiB，并且校验通过 |

## 11. 如果你要开发类似的项目（另一种读卡器、另一套固件）

不依赖具体硬件、始终成立的经验：

1. **先读后写。** 在任何写入之前，让读卡器的读取做到 100% 可重复（两次读取相同、SHA-256 相等、空插槽全为 `0xFF`）。
2. **先备份固件**，两次读取，检查读保护，副本放在两个地方。
3. **以工作台为准。** 电脑上的模型能抓住很多问题，但它在扇区布局、2 MiB 限制和板子的真实芯片上都判断错了。在测量之前一律写“未在硬件上测试”。
4. **不要凭 ID 决定**任何在所有情况下都能安全完成的事（比如按 8 KiB 扇区擦除）。
5. **始终回读校验。** 代价很小，并抓到过真实错误。
6. **先探测再假定**（MCU 的 ID、闪存大小、固件版本）。
7. **把读的和写的分开**，在工具和测试脚本里都是如此。
8. **时断时续的连接几乎总是 GND 或焊点问题。** 在怪软件之前，先晃一晃针脚。
9. 当硬件不允许时（2 MiB 限制、没有 Rd 的 USB-C），**记录这个限制**，不要在软件上硬撑。
10. 把每一次测量（时间、哈希、ID）记入报告。后来的人能节省数周。
11. 如果要设计新板：USB-C 上放 5.1 kΩ 的 Rd 电阻，丝印标注焊盘并提供 NRST 和 BOOT0 焊盘，USB 上加 TVS，卡带线上串联电阻，插槽 5 V 附近去耦，接上 `/UWR` 和 `/CAS2`，如果卡带需要则加 5 V/3.3 V 电平转换，并提供 USB 引导程序（DFU），这样就不需要 ST-Link。

## 13. 本项目相对原版 MD Rewriter 的改进

如果对方问起与 `Epicjoy/md_rewriter` 相比有什么变化，可以这样概括（详情，以及哪些在设备上测试过、哪些没有：`https://github.com/legendaryredfox/md_rewriter/blob/main/docs/improvements/zh-Hans.md`）：

- **程序**按层次重写：任意偶数大小的 ROM、`.smd` 转换、写入后读回校验、芯片名称、“取消”按钮、破坏性操作前的警告、浅色或深色主题和内置指南（F1）。
- **命令行 `mdrewriter-cli`**：`--json` 输出、固定退出码，写入或擦除必须带 `--yes`。
- **固件 1.1**（GCC 和 `make`）：一次就能写好 S29GL064N（1.0 只写入每隔一个字）、按 8 KiB 扇区擦除、识别更多芯片、为 8 MiB 做准备。
- **测试**：程序约 150 个、针对闪存芯片模型的真实 `MD.c`，以及只读台架测试套件。
- **工具**：带备份和校验的 SWD、修复被固件 1.0 写坏的卡带、`.deb` 安装包。
- **文档**有六种语言（pt-BR、en、ru、zh-Hans、hi、ur）：README、分步指南、协议、命令行、卡带支持、台架结果。
- **发现**：芯片是 STM32F103xE，没有 USB 更新，KY / FlashKit 闪存卡带最多容纳 2 MiB。
- **没有改变**：电路板仍是 V1.0；一些额外的芯片只通过了电脑上的测试（完整列表中的 ◇ 标记）。

祝工作顺利。有疑问时，问对方，并去测量。
